# AGENTS.md

FallStack connects ISEP students with companies, internships and career opportunities through talks, stands and networking activities.

## Setup

- Run `scripts/agents/setup.sh <agent>...` once per clone (`claude`, `gemini`, `codex`, `cursor`, `copilot` or `all`; add `--help` for details). On Windows, run `scripts\agents\setup.bat <agent>...`. Do not commit the files it creates.
- Use the Node version in `.nvmrc` and the pnpm version in `packageManager`, then run `pnpm install`.

## Rules

- Do only what the issue or request asks. Record follow-up work as a new issue.
- Never read `.env` files or production tokens. Use `.env.example` to learn which variables exist. Never commit secrets or personal data.
- Branch from an up-to-date `dev` as `<type>/<short-kebab-case-description>`. Open the pull request into `dev`, never `main`. Never work directly on `main` or `dev`.
- Never merge a pull request or open a `dev` to `main` promotion pull request unless asked.
- Commit and push only when asked. Never force-push or rewrite shared history.
- Write Conventional Commits as a one-line header under 72 characters. Write no body, no footer, and no AI co-author or "generated by" lines.
- Ask before destructive actions, major dependency upgrades, or changes to CI or deployment configuration.
- Run the documented checks before review. Never report a check as passing unless you ran it, and never skip or loosen tests, lint rules or CI to get a green result.
- Add or update a decision record in the same pull request when it settles a meaningful architecture or product decision.
- Open pull requests with every section of the [template](.github/PULL_REQUEST_TEMPLATE.md) filled in, the applicable labels, and the author as assignee. Link the issue with `Closes #N`, or `Refs #N` for partial work. Say which of these you could not apply.
